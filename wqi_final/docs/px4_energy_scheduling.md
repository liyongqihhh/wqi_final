# PX4 飞控与论文能量模型的统一调度

## 1. 责任划分

PX4 SITL 执行姿态、位置控制、解锁及降落，不作为真实电池实验。
`battery_manager` 根据 Gazebo 里程计得到水平/垂直速度及滤波加速度，使用已有
Zeng 水平功率、Gong 垂直功率和 Dai 动态推重比修正积分电池能量。
起飞、悬停、巡航、下降、降落均计入，投递后更新载荷；地面设备仍有待机耗电。

PX4 Iris 无载总质量按 SDF 设为 1.535 kg，默认 SJTU 保持 1.477 kg。
这些质量同时进入实际积分、起飞前预测、UGV 停靠负载计算。货物质量进入能耗
模型，但没有动态修改 Iris 的质量与惯性；旋翼、阻力、设备功率和电池参数仍为
工程假设，未完成硬件电流与功率标定。

## 2. 一份 SOC

开启能量约束时 `SIM_BAT_ENABLE=0`，仅启用论文电量源。
`px4_battery_bridge` 将 ROS BatteryState 转换为 MAVLink BATTERY_STATUS：
电压以整包电压提供，ROS 放电负电流转成 MAVLink 正电流，SOC 量化到百分整数。
桥接必须通过 `/fmu/out/battery_status` 的反馈确认，并发布 `SYNCED`。
没有确认、数据过期或低于起飞安全余量时，不允许 PX4 起飞；飞行中桥接丢失请求降落。

桥接和控制器的新鲜度阈值是 2 个仿真秒，另外保留至少 30 秒墙钟卡死保护。
这是为了匹配按仿真时钟发布的电量话题，避免 VirtualBox 低实时因子时把正常的
数据间隔误认为断联；真正的仿真时间过期、时钟倒退或长期停滞仍会拒绝起飞。
PX4 自身的 Offboard 心跳和低电量保护没有关闭，正式实验仍应关闭三维界面。

PX4 v1.16 的外部电池输入没有填充 `time_remaining_s`，零初始化会造成假返航。
安装脚本使用仓库中的独立补丁将此字段设为 NaN，而非关闭 SOC 低电量保护。
该补丁在外部 PX4 源码树应用，重复安装检查后跳过；版本或上下文不匹配时失败，
不会静默修改其他源码。不开能量模型时仍可以使用 PX4 默认电池模拟器。

## 3. 三电池账本

```text
E_UAV_next = E_UAV - P_battery * dt / 3600
E_UAV_next = E_UAV + (eta_UAV_charge * P_input - P_docked_idle) * dt / 3600
P_UGV_charge_pack = P_input / eta_UGV_transfer + P_charger_idle
E_system_used = E_UGV_drive_used + E_UGV_charge_pack_used
                + E_UAV_used - E_UAV_stored
```

UAV 电池存入的能量是系统内部转移，不能再次作为系统能耗。系统能耗等价于三块
电池初末存储能量之差；充电变换损失、停靠设备及充电器待机仍计入。
`charging_input_power_w` 是 UAV 充电器实际输入，不是负的净存储功率。
达到目标 SOC 时截断接受的能量，报告功率按实际接受量计算，并使用 0.2 个百分点
启停迟滞避免频繁切换。ROS 消息存在离散周期和传输延迟，系统级账本允许小幅
积分误差，不应把逐样本误差宣称为严格为零。

## 4. 多任务排序与充电策略

每件物资保持楼栋、楼层、载荷一一对应，即使多个物资送到同一楼栋也不合并丢失。
道路图提供 UGV 点间距离；UAV 预飞行服务给出每个完整返航架次能量及飞行时间。
预测包含 UGV 随货物卸载而变化的能耗、停靠充电时间、到站补电等待和服务期间
UGV 待机。驱动电池留 20% 储备，充电电池留 10%，UAV 留 20%。

```text
J = w_time * T_schedule / 3600 + w_energy * E_system / 100
E_UAV_before_sortie >= E_predicted_sortie + E_UAV_reserve
E_UGV_drive_initial >= E_drive_predicted + E_drive_reserve
E_UGV_charge_initial >= E_charge_source_predicted + E_charge_reserve
```

默认两个权重均为 1，参考尺度为 1 小时和 100 Wh，可用管理器 ROS 参数调整。
`energy_time` 对 1 至 6 件枚举，在这个近似预测模型内选择目标值最小的可行顺序；
7 至 10 件采用三个初始顺序和四轮以内 2-opt。它不是动态场景的全局时空最优算法。
道路图不可用时明确记录欧氏距离回退。

`as_needed` 目标为下一架次预测能量加储备加 1 Wh；`full` 为充满。
车辆沿途充电，不足时保持车辆停止和 UAV 停靠，反馈 `CHARGING`；充电源到储备、
取消或超时均退出等待。正式出发前再次调用预飞行检查，以真实 SOC 为准。
预算不足时拒绝任务，而不是放飞后依赖降落保护。取消/失败不会自动恢复一次配送。
当前批次能量规划以物流中心为起点；未返航的任务完成后，下一批次需要先返回
物流中心，不能在任意停车位置继续使用物流中心的距离预算。

### PX4 起降运行开销

纯几何速度曲线没有包含电机启动、落地检测和上锁确认。短架次尤其容易低估能耗。
PX4 预测额外加入两段悬停等效预算：带货启动默认 20 秒，卸货后落地确认默认
10 秒，参数位于 `uav_control/config/battery_model.yaml`：
`px4_startup_overhead_s` 和 `px4_landing_overhead_s`。

```text
E_predicted = margin * (E_geometric_profile
              + P_hover_loaded * t_startup / 3600
              + P_hover_unloaded * t_landing_confirmation / 3600)
T_predicted = T_geometric_profile + t_startup + t_landing_confirmation
```

这里的功率为电池侧功率。两个时间是基于隔离回归发现遗漏后设置的保守工程假设，
不是论文常数或实物标定结果。它们只增加任务预测，不人为扣除实际电量；运行能耗
仍来自里程计和状态积分。默认 SJTU 不加入这些 PX4 时间。长时间绕障与定位异常
仍可能超出预算，因此还需要多目标实测、预测误差统计和动态重评估。

起飞及降落等待以仿真时钟计时，并保留较宽的墙钟超时保护，避免 VirtualBox 的
低实时因子造成假超时。PX4 只有同时确认落地且解除解锁状态后，才发布 `LANDED`
并允许重新锁到 UGV；不能仅凭几何接触平台就提前完成配送。

PX4 联合模式还会在外部 `generated_models/` 生成一份专用 UGV 描述：为原先只有
外观的停机甲板补上物理承托面。甲板为 `0.75 x 0.75 m`，半对角线约 `0.53 m`，
仍在现有 `0.60 m` 联合导航包络内；高度按 Iris 机体碰撞盒下沿计算，保持
`0.42 m` 的停靠坐标且不在初始锁定时互相穿透。生成器不更改原 UGV 文件、质量、
惯性、地图或导航参数，SJTU 模式继续使用原模型。PX4 原生着陆速度设为 `0.3 m/s`，
飞控、接触及落地判定仍由 PX4/Gazebo 完成，没有持续设置实体坐标来模拟飞行。

正常平台着陆使用 PX4 Offboard 的混合设定值：水平 NED 位置保持、垂直位置为
NaN、校园坐标系的下降速度目标为 `0.30 m/s`，转换到 NED 时补偿估计速度偏移。
暂停下降重新对准时启用垂直位置保持。水平目标持续按项目已有的 ground-truth
校园坐标对齐换算，避免切换普通 `NAV_LAND` 后失去这一对齐而偏离小平台。
推力、姿态、速度和接触仍由 PX4 与 Gazebo 计算。电量同步故障时仍回退 PX4
原生紧急着陆；平台任务只有落地上锁且高度与目标相差不超过 `0.15 m` 才确认，
降到平台旁的地面不能算作成功，停靠服务还会单独检查捕获距离。

完成航点后保持精确目标，而不是最后一个中间设定值。下降前同时检查水平误差
不超过 `0.08 m`、水平速度不超过 `0.15 m/s`；进入下降后采用滞回，误差超过
`0.20 m` 或水平速度超过 `0.375 m/s` 才暂停下降重新对准，避免接触抖动反复
切换模式。暂停时保持真实校园高度的闭环目标，而不是只把估计垂直速度置零。
位置对齐的时变偏移也对应速度偏移；着陆设定值加入
`v_local_NED - (vy_map, vx_map, -vz_map)` 的前馈补偿，避免估计速度偏差引起
接触后再爬升。它仍依赖现有 ground-truth 坐标对齐，不是独立定位算法。

联合启动启用 `use_carrier_home:=true`，通过 `/uav/carrier_home` 获得实际 UGV
中心。任务开始时固定这个返航坐标，配送终点仍使用原楼栋/楼层航点；临起飞电量
预算与飞行使用相同的实际中心。批次规划发生在车辆到达之前，仍使用名义道路点。
甲板话题使用协同节点的仿真时钟。实际任务拒绝超过 3 仿真秒、非 map 坐标或
距离对应停车点超过 2 m 的甲板数据；允许跨节点回调带来的最多 0.25 秒时钟超前，
不是放宽陈旧数据限制。
独立 UAV 默认关闭此参数，继续使用固定返航点。着陆期间车辆必须保持停稳；
这不是运动中着陆，也不是强制设置 Gazebo 实体位置，不代替 PX4 落地检测。
重复降落请求不重置着陆时钟。精确着陆超过 60 仿真秒会退出 Offboard 下降并
请求 PX4 原生紧急着陆，避免任务终止后无限停留在空中；这个失败保护不算任务成功。

### 移动基座运输与 PX4 定位检查

联合启动为 PX4 设置 `moving_base:=true`。PX4 v1.16 在落地静止状态检查 GPS
水平漂移与速度偏置，而机体被 UGV 匀速运输时也可能被 IMU 判为静止。因此仅在
此 SITL 模式设置 `EKF2_GPS_CHECK=863`（默认 1023 中移除水平漂移 bit 5 和水平
速度偏置 bit 7），保留卫星数、PDOP、位置/速度精度、垂直检查和欺骗检查。
这不是关闭 GPS 融合或绕过解锁检查。

同时设置 `IMU_GYRO_CAL_EN=0`，防止 UGV 平稳转弯被地面自动陀螺标定误认为
零偏；启动时清除此前 SITL 运输学习的三组陀螺偏置。模拟 IMU、EKF 偏置估计及
PX4 原生解锁检查仍保留。此设置仅针对 Gazebo SITL，不能复制到实体飞控。
独立 UAV 默认 `moving_base:=false`，恢复原 GPS 检查和自动标定。

起飞服务额外要求当前 PX4 位置、速度有效且数值有限，航向也必须有限；已有的
map 对齐不能掩盖后续定位失效。检查不通过时不接受起飞，协同层不解除停靠。
`heading_good_for_control` 表示飞行中最终磁航向对齐，在地面可能正常为 false，
因此不把它当作地面起飞前置条件，实际解锁继续由 PX4 原生航向检查决定。

### 连续架次的仿真速度辅助

2026-10-06 的用户运行中，前三架次均重新停靠成功，第四架次（宿舍 3、3 层）
在甲板接触后失败。真实高度约 `0.421 m`、运动速度很小，但 PX4 的估计垂直
速度仍大幅变化，原速度补偿会把下降设定值变成上升，打断原生落地判定。
延长任务等待、强制上锁或把地面着陆当作甲板成功不能解决这个问题。

联合 PX4 SITL 启用 `enable_sim_velocity_aiding:=true`，使用 PX4 原生 EKF 的
外部高度和三维速度融合：`EKF2_EV_CTRL=6`，打开高度 bit 1 和速度 bit 2，
不打开水平位置/航向融合。`EKF2_EVV_NOISE=0.01 m/s`。已有 Gazebo 世界
ENU 里程计速度转换为 NED
`(vy, vx, -vz)` 后发布到 `/fmu/in/vehicle_visual_odometry`，每轴方差为
`0.0001 (m/s)^2`。PX4 接口需要有限的完整位置向量才能接受高度，消息位置
填入 `(y,x,-z)`，每轴方差 `0.0004 m^2`；但 EKF 只融合其高度，水平位置
仍来自 GPS。姿态为 NaN，不融合 ground-truth 姿态。`EKF2_HGT_REF=3`、
`EKF2_EVP_NOISE=0.02 m`，使用实际仿真高度避免反复接触时估计高度漂移；
`EKF2_GPS_CTRL=5` 保留 GPS 水平位置及三维速度，关闭 GPS 高度融合。
气压、IMU 和原生解锁/落地检查继续工作。独立模式恢复 GPS 高度默认配置。

速度样本沿用源时间戳；重复、非有限或超过 `0.5` 仿真秒的样本不发布，允许
跨节点最多 `0.25` 仿真秒的时钟超前。必须确认 PX4 的 `cs_ev_vel` 和
`cs_ev_hgt` 实际开启，
且样本与融合状态都新鲜，才能接受起飞。飞行中失去融合时退出 Offboard 并
请求 PX4 原生应急降落；应急降落不算成功配送或甲板停靠。

`/uav/px4/velocity_aiding_status` 发布 `ACTIVE:GAZEBO_VELOCITY_HEIGHT_EKF`、
`WAITING:GAZEBO_VELOCITY_EKF` 或 `DISABLED`。联合启动自动启用此功能；
独立 UAV 默认关闭，不修改 SJTU 飞控后端。精确下降的正 NED 速度设定值不低于
配置的 `0.30 m/s`，避免补偿反向或低于 PX4 的下降检测阈值；重新对准时仍使用
高度保持，而不是继续下降。

末段不再一直用坐标偏移前馈压在甲板上等待。仅在配置的甲板高度（误差不超过
`0.025 m`）、水平误差不超过 `0.08 m`、水平/垂直速度均低于 `0.05 m/s`、
倾斜不超过 15 度、里程计新鲜时，持续稳定 `0.5` 仿真秒后交接给
PX4 `NAV_LAND`。原生模式确认之前继续保持 Offboard，未收到模式确认每
`0.5` 仿真秒重发请求；确认后停止 Offboard 下降。此交接不发布假的 LANDED，
仍必须等 PX4 原生落地和非强制上锁，最后由停靠插件检查真实捕获距离。
地面高度约 `0.055 m` 不能触发甲板交接。

`/uav/px4/landing_fault` 以空字符串表示无应急故障；空中速度融合丢失、
电量同步丢失、精确着陆超时等记录明确原因。正常任务不能把应急落地计为
成功配送；恢复流程仍可确认已经安全落地。稳定甲板接触后的正常原生交接
不是应急降落，也不依赖交接后持续保持外部速度融合标志。

本轮还发现接触时悬停推力估计把甲板支撑误认为旋翼升力，估计值从约 `0.70`
下降至 `0.30`，控制及原生低推力判定不断变化。联合 SITL 使用
`MPC_USE_HTE=0`、`MPC_THR_HOVER=0.71`，固定的是推力映射基准，不是强制
设置电机输出。标定依据为本轮 ULog 的空中稳定悬停窗口，控制器归一化推力
中位数约 `0.705`。PX4 仍实时计算姿态、推力、接触和原生落地；独立 UAV 恢复
`MPC_USE_HTE=1`、`MPC_THR_HOVER=0.5`。此标定只适用于当前固定物理质量的
SITL Iris；若改模型质量/动力参数，必须重新标定，不能当作实体飞控参数。

这属于 **Gazebo ground-truth 速度辅助的理想化仿真**，不是新增 VIO、SLAM
或真实传感器融合能力。它也不修改 Gazebo 实体坐标，不绕过实际接触及原生
落地上锁。实体无人机需要真实速度观测及重新标定，不能直接沿用这些仿真参数。

## 5. 实验设计与验收边界

三策略对照：输入顺序/充满、最短道路/充满、时间能耗联合排序/按需充电。
每个后端、策略、随机种子都重新启动仿真，固定物资、配置的初始三电池电量和地图。
启动后等待服务期间可能已发生停靠充电，因此还必须核对记录中的实际任务起始
SOC；若有差异，应报告或重新采样，不能仅凭启动参数声称初始电量完全相同。
使用 `--energy-ablation --repetitions 1`，以多个种子生成独立运行；普通连续重复
任务不会重置电池，不能用于声称相同初始电量的独立对照。

记录配送成功率、碰撞次数、仿真时间与实时因子、三电池初末 SOC、UAV 积分耗能、
充入能量、UGV 两电池用能、系统净耗能与各阶段持续时间。结果按后端和策略分组，
旧记录缺失策略字段时标为 legacy，不混入新组。失败运行必须保留。

本次发现并修复了旧评测器把初始停靠误记为 `redock_success=true` 的问题。
现在只有运行期间确实经历脱离、重新停靠转换，才计为重新停靠成功。修复前的
记录保留原样，其停靠字段应结合 Action 失败原因和 Gazebo 日志审计，不用于新
版本的停靠成功率；正式统计应使用同一冻结版本重新采集。

2026-10-05 本次隔离验证已完成 PX4 统一电量、物理起飞/悬停/降落和 8% 电量
拒绝测试。65% 起飞测试降落后约为 63.7%，PX4 百分反馈约为 64%，未发生解锁后
或降落后自动恢复满电。原始日志和采样在外部目录：
`/home/wqi/design_final_artifacts/regression_px4_energy_20261005`。

本轮最终低电量短架次从配置 22% 启动，实际任务起始 22.199%，补电等待
