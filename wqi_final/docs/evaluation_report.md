# 当前开发基线验证与实验记录

## 报告范围

本报告记录 `wqi_final` 当前源代码能够复现的构建、自动测试、模型检查、单次运行
和自动指标采集证据。它不是最终论文的完整统计结果。尚未执行的正式实验矩阵、组间
均值和标准差均明确标为待采集，不使用推测值代替实测值。

验证覆盖 2026-07-20 至 2026-07-26，环境为 Ubuntu 22.04、ROS 2 Humble、
Gazebo Classic 和 VirtualBox。系统仅面向电脑端仿真，不包含开发板、PX4 或真实
电池遥测。

### 2026-07-26 阶段六机器人侧动态避障回归

本轮发现旧实现由动态障碍物查询 UGV/UAV 位置并主动让行，这不能证明机器人具有
避障能力。现已改为非合作动态障碍：插件只按场景 YAML 中的固定路线和速度运动，
不读取机器人模型、不减速且不主动改变路线。ground truth 只供独立评测器计算净间距，
不参与机器人控制。

机器人侧完成以下修正：

1. UGV 保持 `SmacPlanner2D + Regulated Pure Pursuit` 的道路规划和路径跟踪。
   360 度激光扫描在地图坐标系中聚类并估计障碍速度，再把未来 `10 s` 的运动轨迹
   投影为 `/scan_dynamic_predictions`。
2. 当前扫描和预测扫描同时进入滚动局部代价地图与全局代价地图。行为树持续重算
   `/plan`，控制器直接跟随更新后的黄色路线；预测扫描使用无限射线清除已离开的
   障碍，不保留固定绕行动作或永久代价残影。
3. UAV 顶部 3D 雷达每 `0.5 s` 根据最近有效障碍重新生成平滑三维路径，通过前视点
   跟随 `/uav/replanned_path`；`1.8 m` 安全球仍作为紧急保护。任务层不再提供
   左、右、上、下固定候选绕点。
4. 四旋翼 Gazebo 插件仍以物理周期更新力和力矩，但把状态和 ground-truth 话题限制
   到配置的 `30 Hz`，降低 VirtualBox 中 ROS 节点 CPU 占用和 Action 响应延迟。
5. 每个动态障碍以 `20 Hz` 发布 ground-truth 里程计；评测器计算真实最小净间距和
   碰撞事件。发生碰撞时即使 Action 完成，该次实验也判定失败。

专项运行回归结果：UGV 在中等密度场景连续运行 `210 s`，未产生反向速度命令；
后方追近冲突采样 `265` 次，其中 `263` 次存在预测占据，最小中心距为 `0.846 m`，
大于 UGV 与障碍碰撞半径之和 `0.67 m`。UAV 穿越物流中心空中动态障碍路线时重规划
2 次，发布 17 条三维更新路径，最大横向绕行偏移 `3.77 m`，最小中心距
`4.091 m`，最终位置误差 `0.053 m`，Action 状态为 `SUCCEEDED`。

隔离的定向冲突回归结果如下。表中障碍路线误差为 0，证明测试期间障碍物没有主动
避开机器人：

| 被测对象与场景 | 任务结果 | 最小中心距离 | 保守表面净间距 | 障碍路线误差 | 其他结果 |
|---|---|---:|---:|---:|---|
| UGV，`low`，种子 42 | `NavigateToPose SUCCEEDED` | `1.414 m` | `0.364 m` | `0.000 m` | 最大指令速度 `0.22 m/s`，完成两次绕行并回线 |

### 2026-08-09 论文算法动态导航回归

本轮以 Koenig、Likhachev 的 D* Lite 和 Missura、Bennewitz 的预测式 DWA 为理论
基础，替换阶段六旧的 `SmacPlanner2D + Regulated Pure Pursuit` 动态控制链。阶段
一至五保持原静态参数，降低改动范围。

新增与修正内容：

1. 新增 Nav2 D* Lite 全局规划插件，保存 `g/rhs`、移动起点修正量和优先队列，
   在代价地图变化时增量修复受影响网格。
2. 新增结构化动态障碍消息和 360 度激光速度跟踪；障碍位置、速度、半径和置信度
   发布到 `/ugv/tracked_dynamic_obstacles`。
3. 阶段六局部控制切换为 DWB，并新增预测碰撞评价器。评价器用候选轨迹与障碍物的
   相对运动求预计碰撞时间，覆盖正面、横穿和斜后方追赶，不执行固定避让动作。
4. 新增路径起始方向评价器，只在车辆静止且返程路径位于车身后方时帮助 DWB 选择
   正确方向原地对齐，解决建筑停靠后零速度死锁；正常直行时不参与评分。
5. UGV 直线路段最高速度由旧版 `0.22 m/s` 提高到 `0.40 m/s`，并使用较长前视、
   限制角加速度和路径方向评价抑制 S 形跟踪。协同能量预算同步使用 `0.40 m/s`。
6. D* Lite 增加 `0.6 m` 起点恢复容差；阶段六道路掩码在铺装边缘外增加 `0.30 m`
   软代价恢复带。当动态会车使车体中心越过一个栅格时，规划器会先引导车辆回到可行
   走廊，而不是因起点占用永久停止。恢复带之外仍为致命禁行区。

## 结论与剩余风险

当前开发基线已满足编译、接口生成、单元测试、lint、模型解析、地图生成、物理动态
障碍和自动报告要求。毕业设计的软件主体已经形成，但应在提交论文前建立最终 Git
标签并在该标签上执行 `evaluation_method.md` 定义的完整矩阵。最终论文
证据仍缺少统一采集的多轮整程数据、成功率/标准差图表、能耗预测误差标定以及加载
与空载对照。UAV 仍使用 Gazebo ground truth 定位；它具有航路边重规划和局部三维
绕行，但不构建在线三维全局占据地图。UGV 在道路间作为移动基地运行，但起飞和
降落期间会停在固定会合点，当前不支持车辆行驶中的动态追踪着陆。这些边界必须在
论文中如实说明。
